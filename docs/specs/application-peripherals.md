# Application peripherals extension

Trusted application assembly may disable native cloud marketing, replace help and feedback actions, render application-owned model-plan content, and handle explicit read-only share candidates. Native runtime, sessions, plugins, files and personal API provider persistence retain their owners. With no extension upstream behavior is unchanged.

The UI extension transports only explicit user-visible message candidates and target context; it never publishes on its own. The application presents selection, disclosure and recipient controls and owns publication and authorization. Reasoning and tool output are excluded. The extension owns no native state and invokes no native cloud endpoints when disabled. Personal API configuration remains usable. Disabled cloud UI does not manufacture provider entitlements.

The application share action hands off the current session's loaded visible messages directly, independently of the native cloud sharing turn-selection inventory. SessionPane waits for a snapshot matching the selected session, closes the native open intent once, then passes all eligible user messages and completed assistant text to the application preview. The application owns explicit message selection; native representative turn/header row IDs must not filter out the associated assistant responses. Empty eligible content still opens the preview with an empty state. Reopening creates a fresh candidate without publishing or including reasoning, tools, streaming answers, or future conversation updates.

Regression: branded assembly hides cloud rewards and preset account plans, preserves API configuration, routes help/feedback/share to injected handlers, and renders unavailable plans without prices or purchase controls. Upstream assembly retains existing behavior.

When an application peripheral is installed, workspace headers expose a compact feedback action before help, including the workspace-entry and narrow layouts. This action shows only its feedback icon at every width, retaining an accessible name and tooltip without visible text. It invokes only `openFeedback`; help-menu issue and feature-report actions invoke that same application handler. The application owns the dialog, drafts, request recovery and backend; the native shell owns no application ticket state. Without peripherals, no extra action is added and upstream feedback behavior is preserved. Optional application dialogs can be controlled without unmounting their contents so application drafts survive closing; the existing always-open contract remains the default.

Application branding substitutes product-owned artwork only. Plugin icons, recommendation images, document badges and detail content retain original artwork. Fixed builtin icon bytes ship as UI assets and resolve against the trusted distribution identity; branding must not trigger upstream CDN requests for these assets or replace them with the product logo.

The application UI public surface exposes the existing native ArrowLeft and Paperclip primitives alongside its existing icon exports, so external feedback consumers use the same dependency without deep imports. Controlled dialogs remember the connected trigger before autofocus and restore it on close; narrow application feedback styles retain an adequate close target.

When native cloud is disabled by application peripherals, the help dropdown omits community, vulnerability and feature-request entries, including while vulnerability configuration is loading. Product documentation invokes `openHelp`, and issue feedback directly invokes `openFeedback` without a native diagnostic draft. Upstream assembly retains its original entries.
