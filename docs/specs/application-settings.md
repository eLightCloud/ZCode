# Optional application settings

Trusted Root assembly may provide application-owned settings sections and model-provider entries. Native UI owns selection, sidebar grouping, model-source tab selection, provider navigation, error isolation and the existing workspace lifecycle. Descriptors contain stable IDs, labels, icons and content renderers; they confer no authorization and persist no business facts.

Sections join the existing basics group or an application-labelled group. Selecting a native section clears the application section. Removed descriptors cannot retain their content. Model entries appear as top-level tabs within the native model settings page, followed by a native custom-provider tab. Application panels use the full page width; provider navigation and add/refresh controls belong only to the native tab. Explicit native provider navigation must override an injected selection. Unconfigured native builds retain their existing layout and actions.

Application panel renderers receive an `openCustomModels` navigation callback for a real transition to native configuration; it does not create a provider or confer access. Model selection belongs only to `ApplicationSettingsProvider`. External model navigation selects the matching application tab; explicit native provider navigation selects the custom-provider tab. Each application panel mounts on first visit and remains mounted while switching tabs to retain its draft; removed descriptors remove their content. Native provider content stays mounted across tab changes. Tab and panel relationships, keyboard navigation and focus indicators use the native accessible Tabs components; small screens retain readable labels and touch targets. No business role, financial state or provider configuration is stored in tab selection.

Application page assembly may select a header target independently of registration order and mark a page standalone. Standalone pages show their own title instead of sibling navigation. Application settings may link to registered pages; unknown or removed IDs do not open stale content. Close returns focus and preserves the mounted workspace.

Public example: an application registers a basics account section, an administration members section, and a managed model entry. The members renderer can request the model entry through the provided navigation callback, retaining only its own non-sensitive filter. All identities, permissions, credentials and budgets remain with application services; no native settings, execution or provider persistence is mirrored.

Regression: test empty assembly, native/application selection, descriptor removal, standalone page isolation, precise model navigation and provider override; exercise return to a workspace with an unsent draft. Reuse semantic themes, keyboard-accessible controls, desktop chrome and mobile layout.
